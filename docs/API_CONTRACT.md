# API Contract

This document defines every endpoint nexus-web exposes — live in Phase 1
and stubbed for Phase 2. The runtime contract is enforced by Zod schemas in
`src/shared/api-contract.ts`; this doc explains what they mean and how
they're meant to be used.

---

## GitHub Releases contract (upstream)

The `/api/updates/*` endpoints proxy the latest stable release from a
public GitHub repo. Configured via the `NEXUS_RELEASES_REPO` env var
(default: `jltps/nexus-releases`).

**Asset naming** (electron-builder defaults): Nexus ships for **Windows and
macOS**, so a release carries both platforms' artifacts. Each release must
contain at minimum the Windows set:

- `Nexus-Setup-<x.y.z>.exe` — the NSIS installer. (The installer matcher in
  `src/lib/github-releases.ts` accepts the versioned name or a bare
  `Nexus-Setup.exe`, falling back to any `*.exe`.)
- `latest.yml` — electron-updater feed, generated by `electron-builder`
  alongside the installer.
- `Nexus-Setup-<x.y.z>.exe.blockmap` — incremental-update blockmap
  (electron-updater can do delta downloads if it's present).

macOS releases additionally carry one or more `*.dmg` installers (one per
arch; Apple Silicon today) and, when present, `latest-mac.yml`. The
`/download` page surfaces the `.dmg` assets directly; the macOS auto-update
feed is **not** wired in Phase 1 (`latest-mac.yml` is read by
`findLatestMacYmlAsset` but unused until a future mac feed route ships).

**Behavior**:

- **Drafts are skipped**: the endpoint only returns releases where
  `draft === false`.
- **Pre-releases are skipped in Phase 1**: `prerelease === false` required
  too. A `?channel=beta` switch is on the Phase-2 roadmap.
- **Empty state**: if no stable release exists, the endpoints return 404
  with a JSON body. The `/download` page renders an empty state instead of
  failing.

## LIVE endpoints

### `GET /api/updates/latest`

**Purpose**: machine-readable summary of the latest stable **Windows**
installer. This LIVE feed is the Windows auto-update channel only; in Phase 1
macOS is download-only (no notarized auto-update feed), so this endpoint and
`latest.yml` intentionally describe the `.exe` asset. macOS `.dmg` builds are
surfaced on the `/download` page, not here.

**Response** (200): `UpdatesLatestResponseSchema`

```json
{
  "version": "0.7.0",
  "releaseDate": "2026-05-28T13:45:00.000Z",
  "url": "https://github.com/jltps/nexus-releases/releases/download/v0.7.0/Nexus-Setup.exe",
  "sha512": "...base64...",
  "path": "Nexus-Setup.exe",
  "notes": "## v0.7.0\n- ..."
}
```

**Failure modes**:

- 404 `no_release` — no stable release yet.
- 502 `no_installer_asset` — release present but contains no .exe.
- 502 `upstream_error` — GitHub API unreachable.

**Headers**: `Cache-Control: public, s-maxage=300, stale-while-revalidate=3600`.

### `GET /api/updates/latest.yml`

**Purpose**: electron-updater's strict YAML feed. **Byte-for-byte copy**
of the upstream `latest.yml` asset.

**Response** (200): YAML body, `Content-Type: application/x-yaml; charset=utf-8`.

Do **not** rewrite the YAML — electron-updater is strict about the format
(`sha512` is base64 of the binary's SHA-512, `path` is the filename
relative to the release URL base, `releaseDate` is ISO-8601).

### Wiring the desktop app

In the desktop repo, set `scribe/app-update.yml`:

```yaml
provider: generic
url: https://nexus-web-joses-projects-64c7bb4d.vercel.app/api/updates/
```

> The host is the project's Vercel team URL. The bare `nexus-web.vercel.app`
> subdomain belongs to an **unrelated** app and must **not** be used for the
> update feed. Swap this for a custom domain once one is configured.

electron-updater will fetch `latest.yml` from this base URL and then
download the installer asset by its `path`.

## Phase-2 stubs

Every stub validates its request body against a Zod schema in
`src/shared/api-contract.ts` and returns:

```json
{
  "status": 501,
  "error": "not_implemented",
  "phase": 2,
  "message": "<name> is part of Phase 2 (accounts & sync) and not yet implemented.",
  "docs": "https://nexus-web-joses-projects-64c7bb4d.vercel.app/docs#<anchor>"
}
```

…or 400 with Zod issues if the body is malformed. The contract is real
even though the handler is not.

### `POST /api/auth/*`

**Schema**: `AuthSignInRequestSchema`

Planned methods: `magic-link`, `google`, `microsoft`. The desktop app
already implements PKCE-based OAuth for the user's *own* calendar
providers; the Phase-2 auth here is for **the user's Nexus account**
(separate concern), to enable sync.

### `POST /api/sync/pull`, `POST /api/sync/push`

**Schemas**: `SyncPullRequestSchema`, `SyncPushRequestSchema`

Delta semantics. Last-write-wins by `updated_at`. Tombstones for deletes
(see `SyncTombstoneSchema`). Per-row UUIDs (the local SQLite uses INTEGER
PKs that collide across devices; sync requires UUIDs).

### `POST /api/backups`, `GET /api/backups/:id`

**Schema**: `BackupBundleSchema` (mirrors the desktop app's
`BackupBundleSchema` v2 from `scribe/src/shared/ipc-contract.ts`).

**Privacy invariant**: the bundle excludes `api_keys` and `oauth_tokens` —
these stay in the app's `safeStorage` and never sync.

When the desktop app's schema bumps, **update this mirror** and document
in the commit message that both repos changed in lockstep.

### `POST /api/shares`, `GET /api/shares/me`, `DELETE /api/shares/:id`

**Schema**: `CreateShareRequestSchema`

Read-only first. Two recipient kinds: by email (auth'd recipient) and by
link (anonymous token). Optional expiry.

### `POST /api/telemetry`

**Schema**: `TelemetryEventSchema`

Opt-in only. Off by default in the app. The contract requires `context` to
contain only scalar values — no transcript text, no note text, no
identifiers, no API keys.

## What lives where

```
src/shared/api-contract.ts         ← Zod schemas (this contract)
src/lib/github-releases.ts         ← typed GH Releases wrapper
src/lib/stub-response.ts           ← phase2Stub() helper
src/app/api/updates/latest/route.ts ← LIVE
src/app/api/updates/latest.yml/route.ts ← LIVE
src/app/api/{auth,sync,backups,shares,telemetry}/*/route.ts ← stubs
docs/API_CONTRACT.md               ← this file
```
